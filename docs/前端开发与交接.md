# C：前端开发与交接

## 本次范围

基于现有 React 18 + TypeScript + Vite 工程增量开发，保持已有接口路径、会话 Cookie 和 CSRF 双提交协议。没有更改后端业务实现、测试断言或 D 负责的 CI 流水线。

- 问题列表：分页、筛选重置页码、加载/空数据/失败重试状态、避免较早请求覆盖新结果。
- 提问：标题 10–150 字、正文至少 20 字、1–5 个去重标签；提交状态及防重复提交；失败保留内容。
- 编辑器：提问和回答共用基础 Markdown 实时预览；支持标题、粗体、行内代码、三反引号代码块、引用和无序列表；常见关键词、数字和字符串着色。仅产生 React 文本，不执行输入中的 HTML。
- 详情：加载失败重试、操作错误提示、操作期间禁用按钮、评论非空和 600 字限制、切换问题时清理正文草稿。
- 悬赏：原生 dialog（键盘焦点、Escape 关闭），整数积分 10–500、天数 1–14 校验；按服务端返回的 expiresAt 显示倒计时。最终权限、积分余额与状态由后端判定。
- 登录/注册：表单校验、密码自动填充语义、提交状态及失败提示。
- 通知：分页、加载/失败/空态、批量已读状态、同页通知红点即时刷新，保留 30 秒轮询。限制通知链接为本站相对路径。
- 排行榜：请求状态、重试、周期切换时避免旧响应覆盖；未知路由提供返回首页入口。
- 样式：窄屏布局、长标题换行、键盘焦点、按钮禁用态。
- 部署：锁定文件配合 npm ci；Docker 构建上下文排除本地依赖；Nginx SPA 回退、静态资源缓存、健康检查；Grafana 自动导入 Prometheus 数据源和仪表盘。

## 本地启动

```bash
cd ~/Desktop/CampusOverflow/frontend
npm ci
npm run dev
```

保持终端运行，打开终端显示的地址（默认 http://localhost:5173）。开发代理把 `/api` 转发到 `http://localhost:8080`。页面能打开不代表后端已启动。后端未就绪时显示服务不可用，属于真实错误提示。

```bash
npm run typecheck
npm run build
```

## Docker / Nginx

在仓库根目录运行（需要 Docker Desktop 或其他 Docker 引擎）：

```bash
docker compose -f deploy/docker-compose.yml config
SPRING_PROFILES=prod docker compose -f deploy/docker-compose.yml --profile observability up -d --build
```

使用 prod 而不启用 demo：当前初始仓库的 demo 数据依赖未完成的领域业务。已实现演示数据依赖后可自行选择 demo。

- 前端：http://localhost（80）；`/healthz` 仅检查 Nginx 存活。
- Grafana：http://localhost:3000；用户名 admin；密码由 GRAFANA_PASSWORD 提供，原 compose 开发默认值为 admin。
- Prometheus：http://localhost:9090。
- `/actuator/health` 转发给后端；未新增向外暴露的指标端点。
- Grafana → CampusOverflow 文件夹自动导入仪表盘，无需手工配置数据源。
- 仪表盘包含：后端可用性、请求速率、5xx 比例、平均响应时间、发件箱积压/死信、声誉对账异常、JVM 堆内存。
- 响应时间是平均值，不是 P95；P95 需要 B/D 在后端启用直方图后另加面板。无请求时部分面板可能无数据；业务指标为空需要检查后端、抓取目标和相关定时任务。
