## 4. 协作规范

- 分支策略：main 为受保护分支，功能开发一律开 feature 分支，命名 `feature/模块名` 或 `fix/问题描述`
- PR 流程：开发 → 本地自测 → push 分支 → 提 PR（关联 Issue）→ 至少 1 人评审通过 → SM 合并
- 合并方式：Squash merge，合并后删除分支
- 提交信息：`type(scope): description`，如 `feat(question): add create question API`
- 文档入库：章程、Backlog、ADR、术语表、运维手册等一律以 Markdown 提交入库

## 5. 会议制度

- 每日站会：每次实验课前 10 分钟，每人汇报：做了什么 / 要做什么 / 阻塞点
- Sprint Review：Sprint 末尾，PO 主导演示增量
- Retro 回顾：Review 后进行，记录：做得好的 / 待改进的

## 6. 质量门禁

- 后端：`mvn clean install` 全绿，JaCoCo 覆盖率 ≥70%（核心聚合 ≥90%，S4 提到 0.80）
- 前端：`pnpm lint` + `pnpm typecheck` 全绿，pre-commit 钩子生效
- 测试：核心功能必须有单测，CI 中测试通过才可合并
- 架构：ArchUnit 测试全通过

## 7. 版本与发布

- 基线版本 v0.1.0（Sprint 0）
- 每个 Sprint 结束打版本标签（如 v0.2.0、v0.3.0...），合并完成后在 Releases 发布
