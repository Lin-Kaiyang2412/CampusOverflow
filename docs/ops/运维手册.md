## 1. 系统拓扑

CampusOverflow 采用**模块化单体**（ADR-001）：一个 Spring Boot 应用内含 Identity / Q&A / Reputation / Discovery 四个限界上下文，前端为 React SPA，由 Nginx 同源托管并反代 `/api/`。

| 组件 | 容器名 | 镜像 | 宿主端口 | 作用 |
|---|---|---|---|---|
| 前端 Nginx | `co-web` | 由 `deploy/frontend.Dockerfile` 构建 | `80` | 托管 SPA 静态资源、反代 `/api/`、`/actuator/health` |
| 后端应用 | `co-backend` | 由 `deploy/backend.Dockerfile` 构建 | `8080` | REST API、会话、领域逻辑 |
| MySQL | `co-mysql` | `mysql:8.0.39` | `3306` | 唯一数据源，Flyway 管理表结构 |
| Redis | `co-redis` | `redis:7-alpine` | `6379` | 会话存储、缓存、AOF 持久化 |
| Prometheus | `co-prometheus` | `prom/prometheus:v2.54.1` | `9090` | 抓取 `/actuator/prometheus` |
| Grafana | `co-grafana` | `grafana/grafana:11.2.0` | `3000` | 仪表盘可视化 |

**关键约束**：MySQL 必须带 `--ngram-token-size=2` 与 `--innodb-ft-enable-stopword=0`（ADR-005 中文全文检索），缺少这两个参数会导致中文搜索静默失效——搜索结果为空但不报错，是最容易漏配的一项。

**时区**：全链路统一 UTC。MySQL 用 `--default-time-zone=+00:00`，JDBC 连接串带 `connectionTimeZone=UTC`，JVM 带 `-Duser.timezone=UTC`。三者任一不一致都会造成时间字段偏移 8 小时。

## 3. 首次部署

### 3.1 一键启动（推荐）

```bash
# 应用栈（web + backend + mysql + redis）
docker compose -f deploy/docker-compose.yml up -d --build

# 应用栈 + 监控栈（prometheus + grafana）
docker compose -f deploy/docker-compose.yml --profile observability up -d --build
```

首次启动顺序由 healthcheck 保证：`mysql`/`redis` 健康后才启动 `backend`，`backend` 起来后才启动 `web`。MySQL 首次初始化建库约需 30–60 秒，backend 的 `retries: 30` 已在 compose 中预留了足够等待窗口。

### 3.2 验证部署

```bash
# 1) 容器全部 Up（healthy）
docker compose -f deploy/docker-compose.yml ps

# 2) 后端存活与就绪探针
curl -s http://localhost:8080/actuator/health | head -c 200
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/actuator/health/readiness   # 期望 200

# 3) 前端可达
curl -s -o /dev/null -w "%{http_code}\n" http://localhost/healthz                            # 期望 200

# 4) 经 Nginx 反代打通后端（同源，无跨域）
curl -s -o /dev/null -w "%{http_code}\n" http://localhost/api/v1/questions                   # 期望 200/401

# 5) 指标已在暴露
curl -s http://localhost:8080/actuator/prometheus | grep -c "^co_"                          # 期望 >0

# 6) 数据库迁移已执行
docker compose -f deploy/docker-compose.yml exec mysql \
  mysql -ucampus -pcampus_dev_pwd campus_overflow -e "SELECT version, description FROM flyway_schema_history ORDER BY installed_rank DESC LIMIT 5;"
```

六项全部符合预期才算部署成功。任一项不符，直接跳到第 8 节对应故障。

### 3.3 纯本地开发（不走 Docker 应用容器）

```bash
# 只起中间件
docker compose -f deploy/docker-compose.yml up -d mysql redis

# 后端
mvn -f backend/pom.xml clean install -DskipTests
mvn -f backend/pom.xml -pl co-bootstrap spring-boot:run

# 前端（另开终端）
cd frontend && npm install && npm run dev
```

前端 dev server 通过 Vite 代理把 `/api` 转发到 `localhost:8080`。

## 4. 配置与密钥管理

### 4.1 环境变量清单

所有变量均有开发默认值，**生产环境必须显式覆盖**。

| 变量 | 默认值 | 是否敏感 | 说明 |
|---|---|---|---|
| `MYSQL_ROOT_PASSWORD` | `root_dev_pwd` | ✅ 是 | MySQL root 密码，仅容器内使用 |
| `DB_PASSWORD` | `campus_dev_pwd` | ✅ 是 | 应用数据库账号密码 |
| `DB_HOST` / `DB_PORT` / `DB_NAME` | `mysql` / `3306` / `campus_overflow` | 否 | 数据源定位 |
| `DB_USER` | `campus` | 否 | 应用数据库账号 |
| `DB_POOL_SIZE` | `20` | 否 | Hikari 连接池上限 |
| `REDIS_HOST` / `REDIS_PORT` | `redis` / `6379` | 否 | Redis 定位 |
| `SERVER_PORT` | `8080` | 否 | 后端监听端口 |
| `SPRING_PROFILES_ACTIVE` | `prod,demo`（compose 内） | 否 | `demo` 会写入演示数据，正式使用须去掉 |
| `CO_FIELD_KEY` | 仓库内硬编码默认值 | ✅ **是** | 字段级加密密钥，**生产必须重新生成** |
| `COOKIE_SECURE` | `false` | 否 | 走 HTTPS 发布时必须改为 `true` |
| `GRAFANA_PASSWORD` | `admin` | ✅ 是 | Grafana 管理员密码 |
| `TZ` | `UTC` | 否 | 容器时区，勿改 |

### 4.2 密钥管理规范

**当前风险（已知项，待整改）**：`deploy/docker-compose.yml` 中 `CO_FIELD_KEY` 带有仓库内硬编码的默认值。任何拿到仓库的人都能解出加密字段。整改方式：

```bash
# 生成新密钥（32 字节 Base64）
openssl rand -base64 32

# 写入 deploy/.env（该文件已被 .gitignore 忽略，禁止提交）
cat > deploy/.env <<'EOF'
MYSQL_ROOT_PASSWORD=<强密码>
DB_PASSWORD=<强密码>
CO_FIELD_KEY=<上一步生成的值>
GRAFANA_PASSWORD=<强密码>
COOKIE_SECURE=true
EOF

chmod 600 deploy/.env
```

**铁律**：
- `.env` 永不入库；**禁止**把密钥写进 `docker-compose.yml`、`application.yml` 或任何代码文件
- 密钥一旦误提交，仅删除文件无效——必须改写 git 历史（`git filter-repo`）并**立即轮换密钥**
- 演示环境与生产环境使用**不同**密钥与密码

## 5. 日常运维

### 5.1 启停

```bash
# 停止（保留数据卷）
docker compose -f deploy/docker-compose.yml down

# 停止并销毁数据卷（⚠️ 数据全部丢失，仅限重建演示环境）
docker compose -f deploy/docker-compose.yml down -v

# 单服务重启（改配置后最常用）
docker compose -f deploy/docker-compose.yml restart backend

# 仅重建后端镜像（代码变更后）
docker compose -f deploy/docker-compose.yml up -d --build backend
```

### 5.2 日志

```bash
# 全栈跟随
docker compose -f deploy/docker-compose.yml logs -f

# 只看后端最近 200 行
docker compose -f deploy/docker-compose.yml logs --tail=200 backend

# 只看错误级别
docker compose -f deploy/docker-compose.yml logs backend | grep -iE "ERROR|Exception"

# 后端业务日志文件（容器内 /app/logs，若挂载了卷）
docker compose -f deploy/docker-compose.yml exec backend ls -l /app/logs
```

### 5.3 数据备份与恢复

MySQL 备份（**演示前一天必做**）：

```bash
mkdir -p backup
docker compose -f deploy/docker-compose.yml exec -T mysql \
  mysqldump -ucampus -pcampus_dev_pwd --single-transaction --routines --triggers \
  campus_overflow > backup/campus_overflow_$(date +%Y%m%d_%H%M).sql
```

恢复：

```bash
docker compose -f deploy/docker-compose.yml exec -T mysql \
  mysql -ucampus -pcampus_dev_pwd campus_overflow < backup/campus_overflow_20261024_1200.sql
```

Redis（会话可丢，如需保留）：

```bash
docker compose -f deploy/docker-compose.yml exec -T redis redis-cli SAVE
docker run --rm -v campus-overflow_redis-data:/data -v "$PWD/backup":/backup alpine \
  tar czf /backup/redis_$(date +%Y%m%d).tar.gz -C /data .
```

**备份策略**：演示前手动全量一次；日常开发按需。备份文件保留在 `backup/`（已在 `.gitignore` 中），不提交。

### 5.4 健康巡检（建议每次站会前跑一遍）

```bash
docker compose -f deploy/docker-compose.yml ps --format "table {{.Name}}\t{{.Status}}"
curl -s http://localhost:8080/actuator/health | python -m json.tool
docker stats --no-stream
```

## 6. 发布与回滚

### 6.1 分支与合并（GitHub Flow）

1. 从最新 `main` 切分支：`feature/xxx` / `fix/xxx` / `docs/xxx`
2. 本地自测：`mvn -f backend/pom.xml clean install` + `cd frontend && npm run typecheck && npm run build`
3. push 分支 → 提 PR → **关联 Issue** → **≥1 名非作者 approve**
4. Squash merge → 删除源分支 → 本地同步 `main`

### 6.2 发布一个新版本

```bash
# 1) 从 main 构建镜像（本地验证）
docker compose -f deploy/docker-compose.yml build

# 2) 打标签并推送（触发 CI images job）
git tag -a v0.2.0 -m "Sprint 1 增量"
git push origin v0.2.0

# 3) 在 GitHub Releases 填写变更说明，附本次演示要点
```

发布前置条件（章程第 9 节）：DoD 全部满足、演示通过、本手册与 `deploy/` 配置已入库。

### 6.3 回滚

```bash
# 方案 A：回到上一个镜像（若镜像打了版本标签）
docker compose -f deploy/docker-compose.yml down
git checkout v0.1.0
docker compose -f deploy/docker-compose.yml up -d --build

# 方案 B：仅回滚代码（数据不回滚，需评估 Flyway 迁移是否可逆）
git revert <坏的提交SHA>
docker compose -f deploy/docker-compose.yml up -d --build backend
```

> ⚠️ Flyway 迁移**默认不可逆**。涉及删列/改类型的迁移必须在 PR 评审中单独标注，并把回滚脚本写入对应 ADR。

## 7. 监控与告警

### 7.1 入口

| 界面 | 地址 | 凭据 |
|---|---|---|
| 应用 | `http://localhost/` | 演示账号 |
| API 文档 | `http://localhost:8080/swagger-ui.html` | 无需登录 |
| Prometheus | `http://localhost:9090` | 无 |
| Grafana | `http://localhost:3000` | `admin` / `$GRAFANA_PASSWORD` |

### 7.2 核心指标与阈值

| 指标 | 含义 | 正常 | 告警阈值 |
|---|---|---|---|
| `co_outbox_backlog` | 事务性发件箱积压（ADR-002） | < 20 | **> 100 持续 5 分钟** |
| `co_outbox_dead_letters` | 死信事件数 | 0 | **> 0 立即人工介入** |
| `co_reputation_mismatches` | 声誉账本对账不一致账户数（FF-8） | 0 | **恒应为 0，非 0 即数据损坏** |
| `http_server_requests_seconds{uri="/api/v1/questions/{questionId}"}` | 问答详情页延迟 | P95 ≤ 300ms | **P95 > 300ms 持续 10 分钟** |
| `jvm_memory_used_bytes` | JVM 堆占用 | < 70% MaxRAM | > 85% 持续 10 分钟 |
| `hikaricp_connections_pending` | 等待连接的请求数 | 0 | > 5 持续 1 分钟（连接池打满） |

### 7.3 PromQL 速查

```promql
# 发件箱积压
co_outbox_backlog

# 详情页 P95
histogram_quantile(0.95,
  sum(rate(http_server_requests_seconds_bucket{uri="/api/v1/questions/{questionId}"}[5m])) by (le))

# 接口错误率
sum(rate(http_server_requests_seconds_count{status=~"5.."}[5m]))
  / sum(rate(http_server_requests_seconds_count[5m]))

# 连接池等待
hikaricp_connections_pending

# 对账一致性（应恒为 0）
co_reputation_mismatches
```

### 7.4 告警规则

告警已落地（Issue #14），共 9 条规则，阈值与 7.2 逐条对应。

| 文件 | 作用 |
|---|---|
| `deploy/alert-rules.yml` | 9 条规则，分 availability / http / pipeline / resources 四组 |
| `deploy/prometheus.yml` | `rule_files` 挂载上述规则，`evaluation_interval: 30s`，投递到 `alertmanager:9093` |
| `deploy/alertmanager.yml` | 分组、抑制规则（critical 抑制同名 warning）；默认不接外部渠道 |
| `deploy/docker-compose.yml` | 新增 `alertmanager` 服务（`observability` profile） |

| 告警名 | 触发条件 | 级别 |
|---|---|---|
| `BackendDown` | `up{job="campus-overflow"} == 0` 持续 1m | critical |
| `HighErrorRate` | 5xx 占比 > 1% 持续 5m | critical |
| `HighLatencyP95` | 全局 P95 > 500ms 持续 5m | warning |
| `QuestionDetailP95Slow` | 详情页 P95 > 300ms 持续 10m（QS-01） | warning |
| `OutboxBacklogHigh` | `co_outbox_backlog > 100` 持续 5m | warning |
| `OutboxDeadLetterPresent` | `co_outbox_dead_letters > 0` 持续 1m | critical |
| `ReputationLedgerMismatch` | `co_reputation_mismatches > 0`（FF-8） | critical |
| `JvmHeapHigh` | 堆占用 > 85% 持续 10m | warning |
| `ConnectionPoolSaturated` | `hikaricp_connections_pending > 5` 持续 1m | critical |

**P95 类告警的隐藏依赖**：必须开启 `management.metrics.distribution.percentiles-histogram.http.server.requests=true`（已在 `application.yml` 配置），否则只有 `_sum`/`_count` 没有 `_bucket`，`histogram_quantile()` 取不到数据、规则永不触发。

启动与验证：

```bash
docker compose -f deploy/docker-compose.yml --profile observability up -d
curl -s localhost:9090/api/v1/rules | grep -c '"name"'   # 规则加载条数
open http://localhost:9090/alerts                        # 当前告警状态
open http://localhost:9093                               # Alertmanager UI
promtool check rules deploy/alert-rules.yml              # 语法校验（有 promtool 时）
```

## 8. 故障处置

| 现象 | 定位命令 | 根因 | 处置 |
|---|---|---|---|
| `co-web` 502 Bad Gateway | `docker logs co-web --tail=50`；`docker ps` 查 backend 状态 | backend 未起来或崩了 | 先修 backend；`restart backend` |
| `co-backend` 反复重启 | `docker logs co-backend --tail=100 \| grep -i "error\|exception"` | 数据库连不上 / Flyway 校验失败 / 密钥缺失 | 查 `depends_on` 健康状态；`SELECT * FROM flyway_schema_history` 核对校验和 |
| backend 启动报 `Access denied for user` | — | `.env` 里 `DB_PASSWORD` 与 MySQL 初始化密码不一致 | 注意：MySQL 密码**只在首次初始化数据卷时生效**，改密码后必须 `down -v` 重建或进库 `ALTER USER` |
| 后端健康但前端列表为空 | `curl http://localhost/api/v1/questions` | Nginx 反代路径写错 / 后端 404 | 核对 `nginx.conf` 的 `location /api/` 与后端 context-path |
| **中文搜索搜不到结果** | `docker inspect co-mysql \| grep -A5 Cmd` | MySQL 缺 `ngram-token-size=2`（ADR-005） | 补参数后 `down -v` 重建（索引需重建） |
| 时间字段差 8 小时 | 对比 `docker exec co-mysql date` 与接口返回 | 时区链路不一致 | 统一 `TZ=UTC` + JDBC `connectionTimeZone=UTC` + `--default-time-zone=+00:00` |
| 登录后立刻掉登录态 | `docker exec co-redis redis-cli keys "co:session:*"` | Redis 不可用 / Cookie `secure=true` 但走 HTTP | 检查 Redis 健康；HTTP 环境将 `COOKIE_SECURE` 设为 `false` |
| Grafana 面板全空 | `curl http://localhost:9090/api/v1/targets` | Prometheus 抓不到 backend | 核对 `prometheus.yml` 的 target 为 `backend:8080`（容器内网名，不是 localhost） |
| `docker build` 后端镜像失败 | 看构建日志中 `mvn` 输出 | 编译错误，或本地改了 pom 未同步 | 本地先 `mvn -f backend/pom.xml clean compile` 复现 |
| `docker compose up` 报端口占用 | `netstat -ano \| findstr :3306` | 本机已有 MySQL/Redis | 停掉本机服务，或改 compose 端口映射 |

## 9. 演示日运行手册

演示当天按此清单执行，**提前 60 分钟**开始：

- [ ] 关闭本机其它 MySQL / Redis 服务，释放 3306 / 6379
- [ ] `docker compose -f deploy/docker-compose.yml --profile observability up -d --build`
- [ ] 等全部容器 `healthy`（`docker compose ps`）
- [ ] 跑第 3.2 节六项验证，全绿
- [ ] 执行 5.3 节 MySQL 全量备份，确认 `backup/` 下有非空 sql 文件
- [ ] 用演示账号走通三条主链路：注册/登录 → 提问 → 回答 → 采纳
- [ ] 打开 Grafana 仪表盘，确认曲线有数据（不要留空面板上台）
- [ ] 关闭屏幕通知；浏览器只留一个标签页
- [ ] 记录演示机 IP，准备热点兜底（不依赖会场 Wi-Fi）
- [ ] **演示前 10 分钟不再重建镜像**，避免现场等构建

**演示故障兜底**：
1. 前端白屏 → 直接开 `http://localhost:8080/swagger-ui.html` 演示 API
2. 后端崩溃 → 展示 Grafana 历史曲线 + 本地截图，说明"可观测性正是在为此服务"
3. 数据库损坏 → `down -v` 重建 + 恢复备份 + 重启（预计 3 分钟，提前演练过）

## 10. 已知限制与风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | `CO_FIELD_KEY` 在 compose 中有硬编码默认值 | 加密字段可被仓库读者解密 | 生产用 `deploy/.env` 覆盖；后续从 compose 移除默认值（见 4.2） |
| R2 | `SPRING_PROFILES_ACTIVE` 默认含 `demo` | 正式环境写入演示数据 | 生产部署显式设为 `prod` |
| R3 | `docker compose` 为单机部署，无多副本 | 无高可用，容器挂了即不可用 | 课程场景可接受；`restart: unless-stopped` 作为兜底（当前未配置，建议补） |
| R4 | 告警规则已配置但未接外部通知渠道 | 告警只在 Prometheus / Alertmanager UI 可见，没人盯着就收不到 | 课程环境可接受；`alertmanager.yml` 预留 webhook 位置，接群机器人后取消注释即可，见 7.4 |
| R5 | MySQL 密码仅在首次初始化数据卷时生效 | 改密码不生效，易踩坑 | 见 8 节对应行 |
| R6 | 覆盖率门禁当前为 0（`domain.coverage.minimum=0`） | 质量门禁形同虚设 | Issue #12，随 Q&A 域层实现一并提至 0.70 |
| R7 | CI 后端单元测试在 `co-qa` 域层红灯 | 流水线不能全绿，阻塞合并 | 依赖 Issue #4（Q&A 领域层实现），见 `docs/team/ci-baseline-note.md` |
