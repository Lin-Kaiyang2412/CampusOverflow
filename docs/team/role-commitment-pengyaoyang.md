## 一、我承诺做到的

1. **主持同步会议**。按章程组织每日站会和周会，记录每个人完成的工作、下一步计划、阻塞点、负责人和截止时间。
2. **维护 Sprint 流程**。推动任务先进入 Issue，再进入功能分支和 Pull Request；检查 Issue、PR、评审、CI 和合并记录是否可以互相追溯。
3. **守住合并规范**。提醒团队遵守分支命名、提交信息、关联 Issue、至少一名非作者评审、CI 通过后再合并的约定；发现堆叠分支或过期基线时及时提醒 rebase 或明确合并顺序。
4. **协调阻塞问题**。对权限、环境、分支冲突、测试失败、部署凭据等阻塞项登记负责人和下一步动作，持续跟进到关闭。
5. **组织 Review 与 Retrospective**。Sprint 结束时按验收标准逐项核对交付物，记录通过项、遗留项和下一 Sprint 的改进措施。
6. **维护过程证据**。保存真实的会议纪要、Issue/PR 链接、Review 结果、CI 运行记录和合并提交，不把其他成员的代码实现写成本人的独立成果。
7. **维护团队材料**。保持成员角色、职责、技能矩阵和团队章程与实际分工一致；人员或职责变化时在下一次同步会上确认后更新文档。

## 三、我接受被这样考核

- 会议没有明确的下一步、负责人或截止时间时，在回顾会上说明原因并补齐。
- PR 缺少 Issue、评审、CI 或验收证据时，不把它标记为流程完成。
- 阻塞项超过约定时间没有进展时，主动升级给 PO 或对应负责人，而不是等待问题自行消失。
- 过程记录只写可核验事实；没有会议或 CI 证据的内容标注为待确认。
